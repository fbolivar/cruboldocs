# AUD-20261110 — Auditoría de seguridad · Crubol-Agent (asistente de IA)

- **Fecha:** 2026-11-10 · **Rama:** `fase/testing` · **Proyecto Supabase:** `dcteuwybqtktwvpfweyr`
- **Alcance:** feature Crubol-Agent — `src/lib/agente/tools.ts`, `src/lib/agente/agent.ts`, `src/app/api/agente/route.ts`, `src/app/api/agente/ejecutar/route.ts`, `src/components/agente/agent-panel.tsx`, migración `016_agente_ia.sql`. Foco: inyección de prompts, autorización/RLS, abuso de costo/límites, aislamiento multi-tenant, privacidad (Anthropic como encargado).
- **Método:** revisión adversarial de código + razonamiento de amenazas sobre los endpoints + suite `npm run test:rls` (179) y `npm run test` (163). Perfil ISO/IEC 27001:2022.
- **Objetivo:** endurecer antes de ampliar el agente (más organizaciones o lectura de contenido de documentos).

## 1. Resumen ejecutivo

El aislamiento multi-tenant del agente es sólido: las herramientas escriben con la sesión del usuario (RLS), el consumo valida permiso + habilitación de forma atómica, el prompt solo recibe el catálogo de la organización activa y la clave de Anthropic vive solo en el servidor; la contención ante inyección de prompts es correcta (las herramientas solo proponen crear catálogo que el usuario ya puede crear, con confirmación humana y sin vías de exfiltración).
Se hallaron **2 Medios** (sin tope de tamaño de entrada → abuso de costo; rutas de API sin protección CSRF) y **3 Bajos** (endpoint de ejecución no condicionado al opt-in; sin límite de ráfaga; una prueba desactualizada); **0 Críticos y 0 Altos**.
Todos los hallazgos se remediaron y re-verificaron en esta misma auditoría (tsc + lint + 163 unitarias + 179 RLS en verde).

**Veredicto: APTO** para seguir en producción con el alcance actual (una organización piloto, solo catálogo). **Condición:** ampliar el agente a más organizaciones o a **lectura de contenido de documentos** exige una re-auditoría previa (ver §4).

## 2. Hallazgos (todos remediados)

| ID | Sev. | Descripción | Evidencia | Remediación aplicada |
|---|---|---|---|---|
| **MED-01** | Media | **Sin tope de tamaño de la conversación enviada a Anthropic.** `parseMessages` limitaba el número de mensajes (≤50) pero no su tamaño: un cliente comprometido podía mandar mensajes enormes y disparar el costo de tokens de entrada dentro del tope mensual. ISO A.8.6. | `route.ts` `parseMessages` (versión previa, sin medir longitud). | Tope `MAX_TOTAL_CHARS = 24_000` sobre el contenido total; si se excede, 400 «Mensajes inválidos». |
| **MED-02** | Media | **Rutas de API sin protección CSRF.** `/api/agente` y `/api/agente/ejecutar` se autentican por cookie y, a diferencia de las Server Actions de Next, no verifican el origen. Un sitio de terceros podría intentar un POST con la sesión del usuario (mitigado por SameSite=lax, pero sin defensa propia). ISO A.8.26. | `route.ts` y `ejecutar/route.ts` (sin chequeo de `Origin`). | Nuevo `isSameOrigin(request)` (`src/lib/http/same-origin.ts`) exigido al inicio de ambas rutas; rechaza 403 si el `Origin` del navegador no coincide con el host (o `NEXT_PUBLIC_APP_URL`). 6 pruebas unitarias nuevas. |
| **BAJ-01** | Baja | **`/api/agente/ejecutar` operaba aunque el agente estuviera apagado.** Solo exigía sesión; corría la acción de dominio (RLS-gated). No es escalada (hace lo mismo que la UI), pero ampliaba la superficie y no respetaba el opt-in. ISO A.8.2. | `ejecutar/route.ts` (sin `isAgentEnabled`/`canManageCatalog`). | Se exige `canManageCatalog(user) && isAgentEnabled()`; 403 «El agente no está disponible» si la función está apagada para la organización. |
| **BAJ-02** | Baja | **Sin límite de ráfaga por usuario.** El tope mensual por organización (200) acota el costo total, pero una ráfaga podía agotarlo en segundos. ISO A.8.6. | `route.ts` (solo `ai_agent_consume`). | Regla `agente:usuario` (20 / 10 min) en el rate-limiter de Upstash; 429 «Demasiados intentos» al excederla. |
| **BAJ-03** | Baja | **Prueba desactualizada deja la suite en rojo.** `security.test.ts` esperaba que Turnstile enviara `remoteip`, parámetro removido a propósito antes (frágil tras CDN). Ajena al agente, detectada al correr la suite. | `tests/unit/security.test.ts:137`. | Aserción corregida: `remoteip` ya no se envía; se verifica `response`. Suite en verde. |

## 3. Controles verificados (sin hallazgos)

- **Aislamiento multi-tenant.** Las herramientas delegan en `saveProcess`/`saveDocumentType`/`savePosition` con la sesión del usuario → RLS impide escribir en otra organización. `ai_agent_consume` es `SECURITY DEFINER` con `search_path = ''`, valida `can_manage_org` y `ai_agent_enabled`, incrementa de forma atómica con tope, y su `EXECUTE` está revocado a `public`/`anon`. El prompt solo recibe el catálogo de la organización activa (`listProcesses`/`listDocumentTypes`/`listPositions`, todos por `scope()`). 179 pruebas RLS en verde (13 específicas del agente: aislamiento, lectura, consumo, permiso, límite).
- **Contención ante inyección de prompts.** El contenido del usuario y el catálogo se tratan como datos; el system prompt lo declara explícitamente. Aunque una inyección lograra forzar una herramienta, esta solo puede **proponer** crear procesos/tipos/cargos que el usuario ya puede crear, con **confirmación humana** por acción. No hay herramientas que devuelvan datos, lean documentos ni hagan llamadas externas → sin vía de exfiltración ni de escalada de privilegios (p. ej. crear un cargo con rol `lider_sig` es algo que un Admin ya hace en la UI; el agente no asigna personas a cargos).
- **Secretos.** `ANTHROPIC_API_KEY` es server-only (`import "server-only"` en `agent.ts`/`tools.ts`, no `NEXT_PUBLIC`), en Vercel como variable cifrada. El cliente (`agent-panel.tsx`) solo llama a las rutas de API. Sin fugas al bundle.
- **Validación de entrada.** `runTool` valida con zod y delega en las server actions, que revalidan. `/ejecutar` valida el nombre de herramienta contra `TOOL_NAMES`. Salida del modelo acotada (`max_tokens` 1024).
- **Privacidad.** En el MVP el agente envía a Anthropic solo la conversación y el catálogo (nombres de procesos/tipos/cargos); **no** el contenido de documentos ni datos de otras organizaciones. Declarado en `/tratamiento-de-datos` §6 (Anthropic como encargado, EE. UU., sin entrenamiento) y en `/terminos` §9.

## 4. Condiciones para ampliar el alcance (re-auditoría obligatoria)

1. **Lectura de contenido de documentos por el agente.** Cambia el perfil de datos enviados a Anthropic (posible dato personal/sensible del cliente) y amplía la superficie de inyección de prompts (el contenido del documento pasaría al prompt). Requiere: minimización/filtrado de lo que se envía, revisión del tratamiento y del consentimiento, y pruebas de inyección con contenido hostil.
2. **Más organizaciones.** Validar el costo agregado (límite por organización vs. presupuesto global), y considerar un límite global de plataforma además del mensual por organización.
3. **Nuevas herramientas con efectos** (editar/eliminar, asignar personas, firmar): cada una exige su propio análisis de autorización; mantener la regla «el agente propone, el humano confirma».
