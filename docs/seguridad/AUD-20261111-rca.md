# Auditoría de seguridad — Causa raíz estructurada (v1.5-2)

**Fecha:** 2026-11-11 · **Auditor:** rol adversarial (skill seguridad-saas) · **Alcance:** migración 055 (`rca_analyses`, `save_rca_analysis`), capa de datos (`getNonconformity` carga el análisis), server action `saveRcaAnalysis`, UI `RcaAnalysis` en la ficha de NC. "Usar como causa raíz" reusa la acción ya auditada `setNcCause`.

## Resumen ejecutivo (3 líneas)
`rca_analyses` (uno por NC) tiene RLS por `organization_id` y FK compuesta `(nonconformity_id, organization_id)`; la escritura pasa por `save_rca_analysis`, que autoriza **igual que `set_nc_cause`** (`nc_or_fail` + `can_manage_nc`, bloquea NC cerrada/anulada) y valida método y `data` como objeto JSON. No hay datos personales ni superficie `anon` nueva; la causa raíz sigue siendo el único campo del flujo (el análisis solo la alimenta). **Veredicto: APTO.**

## Veredicto
**APTO** — sin hallazgos Críticos ni Altos abiertos.

## Hallazgos

| # | Severidad | Hallazgo | Evidencia | Estado |
|---|---|---|---|---|
| RCA-01 | Info | `data` es JSON provisto por el cliente. | La RPC valida `method ∈ {5porques, ishikawa}` y que `data` sea objeto; la server action valida la estructura con zod (listas/pasos acotados). No se ejecuta nada desde `data`: solo se guarda y se muestra. | Mitigado |
| RCA-02 | Info | Dos lugares para "la causa". | `rca_analyses` guarda el método/razonamiento; `nonconformities.root_cause` la causa final; "Usar como causa raíz" las sincroniza vía `set_nc_cause` (ya auditada). Fuente única del flujo = `root_cause`. | Aceptado |

## Verificaciones realizadas
- **Aislamiento multi-tenant:** RLS select `is_active_member`; FK compuesta `(nonconformity_id, organization_id)`; `save_rca_analysis` resuelve la NC con `nc_or_fail` (RLS). Pruebas RLS 055: Beto (org B) no toca ni ve análisis de A; nadie inserta por REST.
- **Autorización:** escritura exige `can_manage_nc(org, process)` (Líder SIG/proceso); la consulta (Sofía) es rechazada; NC cerrada/anulada bloqueada; método inválido rechazado.
- **Integridad:** `unique(nonconformity_id)` → uno por NC; cambiar de método sobrescribe (verificado). `search_path=''`; sin `anon` nuevo.
- **Sin PII:** el análisis es técnico (problema, porqués, causas 6M); no hay datos personales.

## Conclusión
El módulo se puede desplegar. No hay Críticos ni Altos; los ítems Info quedan mitigados/aceptados por diseño (ADR-106/107/108).
