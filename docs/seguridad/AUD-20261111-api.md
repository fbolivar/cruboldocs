# Auditoría de seguridad — API pública de solo lectura (v1.3)

**Fecha:** 2026-11-11 · **Auditor:** adversarial (skill seguridad-saas) · **Alcance:** claves de API + 5 endpoints GET `/api/v1/*`.
**Migración:** `supabase/migrations/046_api_keys.sql` · **Servidor:** `src/lib/api/keys.ts` (auth, token, rate-limit) + `src/lib/api/read.ts` (lecturas) + `src/app/api/v1/*/route.ts` · **UI:** `src/components/admin/api-keys-*.tsx` + pestaña "API".

## Resumen ejecutivo
API REST **solo lectura** por organización, autenticada con **API key Bearer** (guardada solo como **SHA-256**; el token en claro se muestra una vez). Como la API usa el **cliente de servicio** (sin RLS), el control crítico es que **cada consulta filtra explícitamente por el `organization_id` de la key** — verificado en las 5 lecturas. Scopes de solo-lectura por recurso, rate-limit por clave (Upstash), sin dato personal. Sin críticos ni altos.

## Veredicto: **APTO**

## Hallazgos

| # | Severidad | Hallazgo | Evidencia | Estado |
|---|-----------|----------|-----------|--------|
| 1 | Verificado (control crítico) | Sin fuga entre organizaciones | Las 5 funciones de `read.ts` hacen `.eq("organization_id", org)` con el `org` de la key (nunca de la petición); las subconsultas de mediciones/valoraciones también filtran por org + `in(ids)`. El `org` sale de `api_keys.organization_id`, no del request. | OK |
| 2 | Verificado | Token solo-hash; nunca se guarda ni loguea el claro | `generateApiToken` crea `ck_live_<random>`; se guarda `key_hash` (SHA-256, `^[0-9a-f]{64}$`) + prefijo; la verificación compara hashes; el rate-limit usa el hash, no el token. | OK |
| 3 | Verificado | Autenticación/autorización del endpoint | `authenticate` exige Bearer válido no revocado (401), rate-limit por key (429) y **scope del recurso** (403). Sin key → 401. | OK |
| 4 | Verificado | Sin dato personal | `pqrs` **omite** `customer_name`/`customer_contact`; los demás devuelven metadatos. Campos mínimos y paginación (`limit` ≤ 100). | OK |
| 5 | Verificado | Emisión/revocación controlada | `create_api_key`/`revoke_api_key` exigen `can_manage_org` (Admin de organización o Líder SIG); scope y hash validados en la BD; consulta/otra org rechazadas; revocación lógica. RLS select solo para quien administra. Pruebas RLS (14). | OK |
| 6 | Verificado | Errores sin fuga | Respuestas `{error}` genéricas (401/403/429); nunca detalles internos. | OK |
| 7 | Info | Advisors | `api_keys` con política select (no en deny-all); `create/revoke` authenticated-only; anon sigue en 2; `search_path` = 0. | Aceptado |
